# Дневник смен водителя

Node.js (без зависимостей) + одностраничный веб-клиент.

## Запуск

Нужен Node.js 20+.

```bash
npm start        # http://localhost:3000  (PORT, TRIPS_FILE — переменные окружения)
npm test
```

Данные лежат в `data/trips.json`, новые поездки дописываются туда же (атомарная запись через временный файл).

## API

| Метод | Путь | Ответ |
|---|---|---|
| GET | `/api/days` | список дней, в которых есть поездки |
| GET | `/api/trips?date=YYYY-MM-DD` | `{ date, summary, trips }` |
| POST | `/api/trips` | 201 — создана, 200 + `duplicate: true` — уже была, 409 — тот же `id` с другими данными, 422 — ошибки валидации |

`summary`: `count`, `revenue`, `commission`, `net` (на руки = выручка − комиссия), `cash`/`card` — `{count, amount}`.

```bash
curl -X POST localhost:3000/api/trips -d '{"id":"t9","start":"2026-10-01T12:00:00+05:00","end":"2026-10-01T12:20:00+05:00","amount":2000,"payment":"cash","commission":300}'
```

## Решения

- **День поездки** — локальная дата из `start` (с учётом смещения водителя), а не UTC. Иначе поездка в 01:30 по +05:00 попадёт в предыдущий день. Поездка через полночь относится к дню начала.
- **Валидация**: `amount` — целое > 0, `end` > `start`, обе даты ISO 8601 со смещением, `payment` ∈ `cash|card`, `0 ≤ commission ≤ amount`. Суммы — целые (тенге), чтобы не было ошибок float.
- **Защита от дублей** — по `id` (ключ идемпотентности). Повтор с теми же данными → 200, без новой записи. Сравнение времени — по моменту, а не по строке (`08:10+05:00` == `03:10Z`). Тот же `id` с другими данными → 409, запись не перезаписывается.
- Клиент генерирует `id` один раз на заполненную форму, поэтому двойной клик или повтор после сбоя сети не создаёт дубль.
